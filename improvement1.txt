Things I'd flag as real risks, not just nitpicks
Passwordless auth + Basic Auth combo. Reader accounts can have password_hash = None and authenticate with a blank password, and this is accepted over HTTP Basic Auth for OPDS/Subsonic/API clients. That's fine on a trusted LAN, but if this is ever exposed to the internet (which self-hosted media servers often are, via reverse proxy), a "passwordless user" is effectively an unauthenticated account reachable by anyone who knows/guesses the username. Worth either documenting this as "LAN-only by design" explicitly, or gating passwordless accounts behind IP allowlisting.
No rate limiting mentioned on /auth/login or Basic Auth endpoints. Combined with #1, this is a brute-force/enumeration surface worth addressing before any public-facing deployment.
Schema migrations via ad-hoc ALTER TABLE ADD COLUMN rather than a real migration tool (Alembic). This works for additive column changes but will break down the moment you need a rename, a data backfill, a column drop, or a non-nullable column with existing rows. Worth flagging as tech debt now rather than after the schema stabilizes.
No WSGI server specified. The doc says uv run aarkib starts the app, but doesn't say whether that's Flask's dev server or something production-grade (gunicorn/waitress) behind it. If it's still the dev server, that's a real production readiness gap — no proper concurrency, no protection against slow clients.
Job manager is in-process (ThreadPoolExecutor), which is fine for a single-instance homelab app but is a hard ceiling on scaling — worth being explicit that this is an intentional constraint, not an oversight, since someone reading this six months from now might wonder why it's not Celery/RQ.
Python 3.14 minimum is a bleeding-edge choice (very recent release) — reasonable if targeting rolling-release Docker images, but it narrows who can run this outside Docker and is worth a sentence of justification in the doc.
Minor gap: the diagram calls out an FFmpeg Transcoder component, but section 3 doesn't give it a dedicated writeup like the scanner, optimizer, and OPDS layers get — probably just an oversight rather than an actual omission from the code.
